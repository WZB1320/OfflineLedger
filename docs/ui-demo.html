这次拍板新产生的问题 3 项，第 ① 项必须先答复

「增加手动记账」看着只是加个页面，实际它把一条新的写入路径插进了 §4.3 的先合并后判重里。 不先把 ① 定下来就动手写，大概率重现当初「通知 + 账单双记账」那类缺陷——只是这次换成「手动 + 通知」。

① 手动记录要不要参与融合判重？（必须先定）

手动记录没有交易单号，所以 §4.3 第一级「单号精确匹配」对它永远不命中。真正的问题是后面几级。

方案后果风险
A. 不参与
手动记录直接插库		 现金 / 线下场景通常不会有通知，所以平时既没收益也没损失 必然双记账：P0~P1 的典型用法是「先补录历史账单、再日常收通知」。 用户若先手动补录某笔，之后账单或通知再来一遍，就会记两笔 —— 正是 §4.3 当初要消灭的缺陷类
B. 参与（推荐）
走 mergeRecord		 金额 + 商户 + 方向 ±3 分钟内相同即视为同一笔，自动合并，不会双记账。 L2 宽松门天然不开（它的闸门条件是「至少一方是通知来源且该方无商户名」，手动记录不满足） 3 分钟内两笔同金额同商户的合法手动记录，第二笔会被吞。 但同样的风险在两条通知之间本来就存在，不是手动记录独有的

我的建议：B，并给手动记录独立前缀 manual_（按既有纪律，前缀语义决定判重方向，写错等于判据搞反）。 另外「手动记录」与列表里现有的「已手动修正」（分类修正）是两回事，文案上必须分开，否则用户会混淆。

② 记一笔用自建数字键盘，还是系统数字键盘？

  • 自建（本稿采用的）：一个 4×4 GridLayout + 约 100 行 Kotlin。 好处是右下角能固定「保存」，输入路径「输金额 → 点分类 → 保存」三次点击完成，系统键盘不会弹出来遮挡分类
  • 系统键盘：零成本（inputType=numberDecimal），但会顶起半个屏幕、盖住分类网格，保存按钮也得另找位置
  • 记账 App 基本都选自建，因为输入速度就是这个功能的全部体验。但如果你觉得 100 行换这个不值，可以降级

③ 手动记录的分类与标记

  • 保存后回到「流水」并把新记录滚到可见位置（否则用户不知道存没存上）
  • 列表 meta 建议显示「手动」（屏 1 的「全家便利店」那行就是这样），与既有的「已手动修正」区分开。 现在代码里只有 autoClassified 一个布尔，加「手动录入」要再区分一个维度
  • 分类建议必选：手动录入时用户正看着这一笔，让他明确指定比让规则猜更准

设计约束 决定「什么能画、什么不能画」

设计稿必须能在 AppCompat + 原生 View 上落地。下面两条是评审时最容易忽略、但会导致整稿返工的约束。

不能用的（会破坏零依赖 / 体积红线）

  • Material Components —— 引入即约 1 MB。所以：无 FAB、无 Material Chip、 无 BottomNavigationView（底部导航自绘）、无 Material BottomSheet
  • 任何图标库 / 自定义字体 —— 图标一律用「纯色圆点」或 vector drawable 自绘。 底部导航因此只有文字没有图标，靠 3px 指示条 + 颜色区分选中态
  • 阴影（elevation）表达层级 —— 用 1px 边框 + 底色差代替。Dialog 也不带投影
  • 网络资源（字体/图标 CDN）—— App 本来就离线，设计稿也不该联网

能用的（都是零成本原语）

  • 圆角：XML shape drawable，任意半径
  • 按压态：selector drawable 换底色，替代 ripple
  • 底部导航：LinearLayout + 3 个 TextView，指示条是一个 16×3 的 shape
  • 弹层 / 对话框：Dialog + 自定义布局，自绘 bottom sheet 与居中 Dialog
  • 可滚动 Dialog：外层固定高度 + 中间 ScrollView + 底部按钮同级固定 —— 原生就能做到，不需要任何库
  • 分组列表：RecyclerView 的 getItemViewType 返回 header / row 两种类型
  • 数字键盘：GridLayout + 16 个 Button，纯布局

屏 8 · 首次安装空态 把首次安装的操作顺序直接写进提示：授权 → 导入历史 → 日常自动。 强调「先导入账单」是有依据的——账单是唯一 100% 完整且自带商户名的来源（方案 §0）， 先导入能让第一屏就是「已归类、可看」的状态，而不是一堆「未识别商户」。
空态里的「导入账单」是内容区的主动作（不是底栏按钮）——底栏现在归导航， 且空态下用户唯一该做的事就是导入，把它放在视线中心比放在栏里更对。

刻意没做的事

不在本稿范围内

  • 深色模式：主题是 DayNight，但目前只有一套浅色值。补 values-night 是一块独立工作量，属新增决定
  • 详情页：点击记录直接进修正弹层，暂不做二级页
  • 图表库：统计页只有条形与进度条，不引任何图表库
  • 年度统计：属 P4，现在设计它等于提前解冻冻结项
  • 改动金额格式：-¥32.00 与适配器现状一致，不改成「红色数字不带负号」

落地顺序建议

  • 第一步只做不加功能的改造：底部导航 + 按日分组 + 点击修正 + 状态条压行。 这几项不碰数据层，风险最低，改完就能看
  • 第二步做导入结果 Dialog：纯 UI，也不碰数据层
  • 第三步才做记一笔：它要动 sourceId 前缀与判重语义， 必须先定「新产生的问题①」，并配套单测（构造「手动 + 通知同金额同商户」的重复场景）
  • 理由：AGENTS.md 要求每次改动配套测试且全绿；把不碰数据层的 UI 改动先落地， 能避免「UI 和数据层同时改、测试红了分不清是谁的锅」
本文件是设计稿，不是实现。所有金额、商户名与门店均为虚构占位（门店一律写作 XX广场店），不含任何真实账单数据； 文件完全自包含、零外部依赖，可直接离线打开（与 App 本身的离线约束一致）。
